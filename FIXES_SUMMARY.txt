ISSUE #1: CHAT SYSTEM CRASH - FieldError
================================================================================

ERROR: django.core.exceptions.FieldError: Cannot resolve keyword 'is_read'
LOCATION: /chat/<user_id>/ endpoint
SEVERITY: 🔴 CRITICAL (App crash)

ROOT CAUSE:
-----------
The Message model was refactored to use MessageReadStatus for read tracking,
but the views.py still contained old code trying to filter/update on non-existent
'is_read' field.

FIXES APPLIED:
--------------
File: accounts/views.py

Location 1 (Line ~892):
  ❌ OLD: Message.objects.filter(..., is_read=False).update(is_read=True, ...)
  ✅ NEW: for msg in unread: msg.mark_as_read_by(request.user)

Location 2 (Line ~914):
  ❌ OLD: Message.objects.filter(..., is_read=False).update(is_read=True)
  ✅ NEW: for msg in unread: msg.mark_as_read_by(request.user)

Location 3 (Line ~1952):
  ❌ OLD: Message.objects.filter(..., is_read=False).update(is_read=True, ...)
  ✅ NEW: for msg in unread: msg.mark_as_read_by(request.user)

IMPLEMENTATION PATTERN:
-----------------------
❌ WRONG:
    Message.objects.filter(sender=other_user, receiver=request.user, is_read=False)
    .update(is_read=True)

✅ CORRECT:
    unread = Message.objects.filter(
        sender=other_user,
        receiver=request.user
    ).exclude(read_statuses__user=request.user)
    
    for message in unread:
        message.mark_as_read_by(request.user)

RESULT:
-------
✅ Chat page loads without error
✅ Messages display correctly
✅ Read status tracked via MessageReadStatus model
✅ No database errors

WHY THE REFACTOR WAS NECESSARY:
-------------------------------
1. Scalability: Direct is_read field doesn't work for group chats
2. Flexibility: Multiple users can read same message
3. Audit Trail: read_at timestamp for each reader
4. Performance: Separate model allows indexing on user+message
